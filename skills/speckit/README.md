# Spec Kit

Optional GitHub Spec Kit feature workflow (`templates/commands`). Default spec-driven path in this kit is **OpenSpec** (`core`). Use Spec Kit only when the target already has `.specify/` and the user asked for it.

Adapted from [GitHub Spec Kit](https://github.com/github/spec-kit): `speckit-plan` names the agent context file per client instead of only the Cursor rule file.

- **[speckit-constitution](./speckit-constitution/SKILL.md)** — project constitution
- **[speckit-specify](./speckit-specify/SKILL.md)** — feature specification
- **[speckit-clarify](./speckit-clarify/SKILL.md)** — clarifying questions on the spec
- **[speckit-plan](./speckit-plan/SKILL.md)** — implementation plan
- **[speckit-tasks](./speckit-tasks/SKILL.md)** — `tasks.md` with dependencies
- **[speckit-analyze](./speckit-analyze/SKILL.md)** — consistency of spec / plan / tasks
- **[speckit-checklist](./speckit-checklist/SKILL.md)** — requirements checklist
- **[speckit-implement](./speckit-implement/SKILL.md)** — execute the plan from `tasks.md`
- **[speckit-taskstoissues](./speckit-taskstoissues/SKILL.md)** — tasks → GitHub issues
